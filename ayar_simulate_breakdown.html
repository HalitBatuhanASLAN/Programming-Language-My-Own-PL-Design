Genel Mimari — simulate() nasıl çağrılır?

simulate() iki yerde çağrılır: _exec_train_stmt() ve _exec_evaluate_stmt() (ve top-level _exec_eval_stmt()). İkisi de aynı fonksiyonu kullanır, tek fark is_train_split parametresi.

def simulate(model: ModelRecord, is_train_split: bool) -> Dict[str, float]: hp = model.hyperparams # field dict'i: {'k': 3, 'distance': 'euclidean', ...} mt = model.model_type # 'KNN', 'DecisionTree', 'SVM', 'NaiveBayes', 'LogisticRegression' # ADIM 1: model tipine göre base accuracy hesapla (hyperparametreden) acc = formula(hp, mt) # ADIM 2: train split ise +0.07 bonus ekle if is_train_split: acc += _TRAIN_BONUS # _TRAIN_BONUS = 0.07 # ADIM 3: [0.0, 1.0] arasına clip acc = min(1.0, max(0.0, acc)) # ADIM 4: diğer 3 metriği acc'den model-spesifik offset ile türet f1, precision, recall = derive(acc, mt) return {'accuracy': clip(acc), 'f1': clip(f1), 'precision': clip(precision), 'recall': clip(recall)}

_TRAIN_BONUS Mekanizması (Step 2) — Neden 0.07?

E-Train çağrıldığında is_train_split=True → acc += 0.07

E-Evaluate çağrıldığında is_train_split=False → bonus yok

Bu mekanizma şunu simüle eder: model kendi üzerinde eğitildiği veriyi daha iyi tanır → train accuracy her zaman ~0.07 yüksek olur.

Örnek: KNN k=3 E-Train: acc = 0.88 + 0.07 = 0.95 (train_accuracy = 0.95) E-Evaluate: acc = 0.88 + 0.00 = 0.88 (eval_accuracy = 0.88) gap = 0.95 - 0.88 = 0.07 threshold=0.06 → 0.07 > 0.06 → overfit = TRUE threshold=0.08 → 0.07 < 0.08 → overfit = FALSE

CRITICAL: gap her zaman tam olarak 0.07 çünkü _TRAIN_BONUS sabit. Threshold seçimi bu sabit gap'e göre yapılmalı.

ModelResult Struct — Hangi field nerede kullanılır
@dataclass class ModelResult: train_accuracy: float # E-Train'den gelir, +0.07 bonus dahil # P-AnalyzeOverfitting'de gap hesabında kullanılır eval_accuracy: float = 0.0 # E-Evaluate'ten gelir, bonus YOK # ← E-Collect tarafından HİÇ dokunulmaz (bug fix!) # P-AnalyzeOverfitting val_acc olarak bunu okur overfit: bool = False # P-AnalyzeOverfitting tarafından set edilir underfit: bool = False # P-AnalyzeOverfitting tarafından set edilir rank_key: float = 0.0 # P-Compare tarafından set edilir metrics: Dict[str,float] = field(default_factory=dict) # başta 4 metrik, E-Collect sonrası sadece seçilenler

eval_accuracy neden ayrı? E-Collect collect metrics [f1, precision] derse metrics dict'ten accuracy silinir. Ama P-AnalyzeOverfitting val_acc olarak accuracy okumak zorunda. Eğer ayrı field olmasaydı → metrics.get('accuracy', 0.0) = 0.0 → tüm modeller underfit olarak taglanırdı. Gerçek bug, sample_2.ayar ile bulundu.

E-Train vs E-Evaluate farkı — kodda tam olarak nerede
def _exec_train_stmt(self, node): full_metrics = simulate(model_record, is_train_split=True) # +0.07 if model_name not in self._M: entry = ModelResult( train_accuracy = full_metrics['accuracy'], # 0.07 bonuslu eval_accuracy = full_metrics['accuracy'], # şimdilik aynı metrics = dict(full_metrics), ) else: entry.train_accuracy = full_metrics['accuracy'] # update self._M[model_name] = entry def _exec_evaluate_stmt(self, node): eval_metrics = simulate(model_record, is_train_split=False) # bonus yok if model_name not in self._M: entry = ModelResult(train_acc=eval_metrics['acc'], ...) # train olmadan else: entry.eval_accuracy = eval_metrics['accuracy'] # eval_accuracy güncelle entry.metrics = dict(eval_metrics) # metrics güncelle # train_accuracy KORUNUR — overfit analizi için lazım!
Tam Örnek: KNN k=3, threshold=0.06
simulate(KNN{k=3}, is_train_split=True): acc = max(0.60, 0.94 - 3*0.02) = max(0.60, 0.88) = 0.88 acc += 0.07 → acc = 0.95 f1 = 0.95 - 0.01 = 0.94 precision = 0.95 + 0.01 = 0.96 → clip → 0.96 recall = 0.95 - 0.02 = 0.93 → ModelResult(train_accuracy=0.95, ...) simulate(KNN{k=3}, is_train_split=False): acc = 0.88 (no bonus) f1=0.87, precision=0.89, recall=0.86 → entry.eval_accuracy = 0.88 P-AnalyzeOverfitting (threshold=0.06): gap = train_accuracy - eval_accuracy = 0.95 - 0.88 = 0.07 0.07 > 0.06 → overfit = TRUE P-AnalyzeOverfitting (threshold=0.08): 0.07 < 0.08 → overfit = FALSE
